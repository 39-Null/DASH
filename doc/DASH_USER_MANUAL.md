**最重要的一件事**：首次打开时，请等第一栏的状态变成「待机」再操作。在「待机」出现之前，点击任何按钮都不会有反应，因为模型还没加载到你的手机里。

## 一、这是什么

DASH 微表情皮套人是一个**在手机浏览器里运行**的实时表情演示应用。打开它，你的脸会被实时解析成 52 个表情系数（BlendShape），并驱动屏幕上的 3D 角色（皮套人）同步做出相同的表情。

| 输入方式 | 效果 | 适合场景 |
|---|---|---|
| **摄像头** | 皮套人实时模仿你此刻的表情 | 现场演示 |
| **照片** | 皮套人摆出照片里的那一帧表情 | 展示单帧效果 |
| **视频** | 皮套人逐帧模仿视频中的表情变化 | 回放一段表演 |

本演示全程在手机本地推理，图像不会上传到任何服务器。

## 二、首次使用：请先等待模型加载

### 2.1 打开页面

用手机浏览器打开演示地址。页面会**立刻显示出来**，但这不代表可以使用——此时模型还在下载。

### 2.2 等待状态变为「待机」

页面顶部的状态栏是判断「能不能用」的唯一依据：

| 状态 | 含义 | 你可以做什么 |
|---|---|---|
| 加载中 | 模型正在下载到你的手机 | 等待，先不要操作 |
| **待机** | 模型已就绪（来自本地缓存） | **可以开始使用** |

**首次使用约需 5 分钟。** 这段时间模型正在从服务器加载到你的手机本地，请耐心等待。**等到第一栏出现「待机」状态，再选择文件或打开摄像头。**

**为什么需要等？** 模型文件较大，必须先完整加载到本地，之后才能实时推理。加载完成后会缓存在手机里，**再次打开通常不需要重新等待**。

**网络提示**：极少数情况下**校园网可能限制加载**。如果长时间无法进入「待机」状态，请**切换到移动数据流量**再试。

## 三、页面结构

页面从上到下分为三栏（ZONE），另有一个顶部状态栏。

### 3.1 状态栏（第一栏）

左侧为应用名称，右侧为当前状态与模型来源。右侧显示「待机（模型来自本地缓存）」表示模型已就绪；若显示「加载中」，请继续等待。

### 3.2 输入区（ZONE 01）

**标题：把你的表情放上来。**

| 控件 | 作用 |
|---|---|
| 拖放区 | 把照片或视频文件拖到这里（桌面浏览器更方便） |
| **用摄像头开始** | 调用手机摄像头，实时驱动皮套人 |
| **浏览文件** | 从手机相册或文件中选择照片、视频 |

模式开关：**仅面部识别**（默认，当前可用）只驱动面部表情；**全体识别（二期）**为身体加面部，目前尚未开放。

底部说明：全程本地运行，不上传任何图像。

### 3.3 皮套人预览（ZONE 02）

页面启动时只加载感知模型，**皮套人按需加载**：第一次开始演示、开始性能测试或手动切换皮套人时，才会下载并解析 VRM。
下载与解析期间，预览区底部会显示 `下载皮套人 45% · 2.4 / 5.3 MB` 或 `解析皮套人模型…`；加载完成后再次切换会命中手机本地缓存。

加载完成后，可以用**手指拖动旋转视角**，用**双指捏合**缩放。

| 控件 | 作用 |
|---|---|
| **皮套人** | 在多个 VRM 之间切换；切换会保留当前相机角度与缩放，不会重置视角 |
| **视角：面部** | 一键回到系统默认的面部视角 |
| **感知模型：mediapipe-task** | 选择表情识别模型；日常演示保持默认即可 |
| **网格叠加** | 勾选后在画面上叠加人脸网格线 |

如果某个皮套人下载失败，页面会保留当前模型并显示错误原因，不会把预览区清空。

### 3.4 性能测试（ZONE 03）

在皮套人预览与「了解更多」之间，可以一键测试当前设备能否达到项目的硬约束（30 FPS / 33 ms 帧预算）。

| 控件 | 作用 |
|---|---|
| **信号源** | 内置头像（不显示在页面上）、本地图片、本地视频、摄像头 |
| **方式 / 数值** | 按时长（默认 30 s）或按帧数（默认 300 帧） |
| **开始测试 / 中止** | 测试期间实时显示 FPS、感知耗时、rig+渲染耗时 |

测试结束后给出「通过 / 通过（有告警）/ 未通过」，判定依据是平均帧率、平均工作量与 P95 工作量：
平均帧率 ≥ 30、平均工作量 ≤ 33.3 ms、P95 工作量 ≤ 40 ms 才算通过；P95 落在 33.3–40 ms，
或工作量超预算帧超过 10%，会显示「通过（有告警）」。同时列出数据来源、分辨率、加载耗时、
视频/摄像头帧率、调度诊断与环境信息。结果可以复制为 Markdown，或下载 JSON / CSV。

页面上会明确标注**本次是否调用摄像头**：测试内置头像、本地图片或本地视频时不会打开摄像头；
所有来源的画面都只在本机处理，不会上传。

## 四、三种输入方式的操作步骤

### 4.1 用摄像头（实时）

1. 确认状态栏显示「待机」。
2. 点击 **用摄像头开始**。
3. 浏览器弹出摄像头权限请求时，点击**允许**。
4. 把脸放进画面中央，保持光线均匀、不要背光。
5. 皮套人会实时模仿你的表情。

停止：点击页面上的停止按钮，或刷新页面。

### 4.2 用照片（单帧）

1. 确认状态栏显示「待机」。
2. 点击 **浏览文件**，选择一张人脸照片。
3. 等待处理，进度会显示在第一栏。
4. 皮套人摆出照片里的那一帧表情。

**照片要求**：正脸、清晰、脸部占画面比例较大。侧脸、遮挡、远景都会降低识别效果。

### 4.3 用视频（逐帧）

1. 确认状态栏显示「待机」。
2. 点击 **浏览文件**，选择一段人脸视频。
3. 等待处理，进度会显示在第一栏。
4. 皮套人逐帧模仿视频中的表情变化。

**视频建议**：10 秒以内、近景人脸、画面稳定。视频越长处理越慢，首次演示建议先用短视频验证。

**操作顺序不能反过来**：先等「待机」，再选文件。在「加载中」状态下点击按钮不会有任何反应——这不是故障，是模型还没准备好。

## 五、功能说明

### 5.1 视角控制

- 点击 **视角：面部**：回到默认的正面视角。
- 手指拖动：旋转视角。
- 双指捏合：放大或缩小。

### 5.2 网格叠加

勾选后，画面上会叠加人脸网格线。它有两个用途：

- **看清模型「看到了什么」**——网格是否正确贴合你的脸。
- **排查问题**——如果网格没有对准脸，说明检测失败，表情自然也不会跟随。

### 5.3 感知模型选择

`mediapipe-task` 是当前默认模型。切换不同模型会改变表情的还原风格；日常演示保持默认即可。
这个下拉只列出感知模型，不会与皮套人选项混在一起。

### 5.4 皮套人选择

标题行右侧的「皮套人」下拉用于切换 VRM 角色。切换时保留当前相机角度、缩放和视角预设，
并重新绑定骨骼；如果新模型加载失败，当前模型继续可用。

### 5.5 性能测试

- 想测真实摄像头场景：先在 ZONE 01 打开摄像头，再把信号源选为「摄像头」，测试会复用同一路画面；
  页面会显示「将调用摄像头」。
- 想在无摄像头环境复测：用「内置头像」或选择一段人脸视频，页面会显示「未调用摄像头」。
- 无论哪种来源，画面都只在本机处理，**不会上传**；测试结果也只留在页面内，除非你主动导出。
- 测试期间请保持页面在前台；切到后台会中止测试并标记本次结果无效。
- 结果中的 FPS 与工作量只代表本次测试环境；判定以工作量为主，帧间隔受屏幕刷新率量化影响，
  只作调度诊断。

### 5.6 仅面部识别 / 全体识别

当前版本只开放**仅面部识别**。「全体识别（二期）」为预留功能，尚未开放，点击不会生效。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 一直显示「加载中」 | 模型还没下载完 | 继续等待，首次约 5 分钟 |
| 等了很久仍不进入「待机」 | 校园网受限 | 切换到移动数据流量 |
| 点击按钮没反应 | 状态还不是「待机」 | 等状态变为「待机」再操作 |
| 皮套人不动 | 没有检测到人脸 | 把脸放进画面中央，光线均匀 |
| 表情不跟随 | 检测质量差或设备负载高 | 关闭其他应用，靠近镜头重新开始 |
| 预览区空白 | 皮套人还没加载 | 等待预览区底部的下载/解析提示完成 |
| 切换皮套人失败 | 网络中断或模型文件缺失 | 页面会保留当前模型；检查网络后重试 |
| 性能测试未通过 | 设备性能不足或后台占用高 | 关闭其他应用，用摄像头/视频复测；以真机 Chrome 数据为准 |
| 性能测试提示结果无效 | 测试中切到了后台 | 保持页面在前台，重新测试 |
| 手机发热或卡顿 | 设备性能不足 | 保持「仅面部识别」，降低分辨率 |

## 七、隐私说明

- **全程本地推理，不上传任何图像。**
- 图像只在你的手机浏览器内处理，不经过服务器。
- 模型首次从服务器下载，之后从手机本地缓存加载。
- 性能测试使用的图片 / 视频 / 摄像头画面同样只在本地处理；测试结果只留在页面内，除非你主动导出。
- 本演示不保存、不上传你的人脸数据。

这是一个处理人脸的演示。让使用者清楚知道数据去了哪里，是这类应用的基本要求。
